## 1. EIDOS

**Role:** Creator / independent R&D  
**Repository:** [arku75/EIDOS](https://github.com/arku75/EIDOS)

### Problem

Most AI systems are session-bound: they answer, forget and depend on a single model context.

### Direction

EIDOS explores a persistent local-agent architecture where memory, graph state, agents, tools, verification and capability reuse are separate system layers.

### Engineering themes

- persistent memory and graph state;
- multi-agent / Colony coordination;
- arbitration;
- browser and desktop computer use;
- effect verification;
- reusable capability learning;
- self-edit experiments with rollback;
- local model/tool adapters;
- a dedicated Desktop 2 workspace.

### What makes the project useful as portfolio evidence

EIDOS is not presented as a finished AGI product. The repository explicitly distinguishes between code that exists, code that is wired, paths that were executed, measurable effects and capabilities reused later.

That evidence discipline is part of the project itself.

## 2. msmKALI

**Role:** Workflow/automation builder  
**Repository:** [arku75/msmKALI-automatization-](https://github.com/arku75/msmKALI-automatization-)

### Problem

OnePlus 7 Pro recovery, Windows ARM, root and Kali/NetHunter workflows involve many separate tools and risky device states.

### Direction

The project organizes those steps into a guided, verification-oriented workflow for a real GM1913 device.

### Engineering themes

- device-state detection;
- backup-first operations;
- checksums and verification;
- recovery paths;
- guided automation;
- Windows ARM / Android / Kali experimentation.
