## How I work

I am an **AI-native builder**, not a traditional career software engineer.

My role in a project is to define:

- what the system should do;
- what inputs and outputs matter;
- architecture and workflow boundaries;
- what the AI/tools are allowed to do;
- what counts as success;
- how the result is tested and verified;
- what should be automated, retained or rolled back.

I use coding agents, local and cloud models, APIs, automation frameworks and conventional development tools as implementation collaborators.

## Evidence over presentation

My preferred engineering loop is:

```text
specify
→ implement
→ execute
→ observe effect
→ verify
→ document
→ reuse or roll back
```

I do not treat generated code, a successful command return or a convincing model response as proof that the intended effect happened.
