## About me

I am an **AI-native builder** focused on turning ideas into working systems through AI-assisted engineering.

My work combines local language models, coding agents, automation, APIs, browser/desktop tooling, persistent memory, knowledge graphs and verification loops. I use AI as an implementation collaborator while I define the product behavior, architecture, constraints, workflows and acceptance criteria.

My main project is **EIDOS**, a local-first persistent agent runtime exploring long-lived memory, reusable capabilities, multi-agent coordination, controlled computer use, action-effect verification and rollback-oriented self-repair.

I am especially interested in systems where AI does more than answer questions: it can **use tools, observe effects, retain state, coordinate work and improve repeatable workflows**.

## Flagship project

### [EIDOS — Persistent Local Agent Runtime](https://github.com/arku75/EIDOS)

EIDOS is my main research and product project.

It explores a system architecture built around:

- persistent memory and graph state;
- multi-agent / Colony deliberation;
- one arbitration layer for final decisions;
- browser and desktop interaction;
- action → observed effect → verification loops;
- reusable capability learning;
- local model and tool adapters;
- isolated self-edit and rollback research;
- a dedicated **Desktop 2** workspace for agent interaction without taking over the user's primary desktop.

> A convincing answer is not the same thing as a verified effect.

The public repository deliberately separates **implemented**, **wired**, **executed**, **measured** and **reused** capabilities instead of treating documentation as proof.

[Explore EIDOS →](https://github.com/arku75/EIDOS)

## How I build

My workflow is deliberately verification-oriented:

```text
idea
  ↓
specify behavior
  ↓
use AI / agents to implement
  ↓
run it
  ↓
observe the real effect
  ↓
verify
  ↓
document
  ↓
keep, improve or roll back
```

I care about the difference between:

- code existing;
- code actually being connected;
- a path being executed;
- a measurable effect being observed;
- a learned capability being reused later.

That distinction is central to EIDOS and to how I evaluate AI-generated software.
